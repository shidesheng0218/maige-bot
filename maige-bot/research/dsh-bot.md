# dsh-bot 参考研究

> 来源：https://github.com/wqty123/dsh-bot （DeepSeek Harness 生态的常驻代理实体插件，社区项目）
> 调研日期：2026-10-13

## 它是什么

一个「不属于任何会话」的 bot 实体：实例、记忆、任务队列都在 `$DSH_HOME/bot/` 下，
会话关掉、上下文压缩、机器重启，它都还在。配 7 个 `bot_*` 工具 + 执行器 + 审批闸门 + 入站连接。

## 核心设计哲学（按对麦格的价值排序）

### 1. 记忆是文件，不是向量库
- `.md` 文件树，用户能打开、能改、能从磁盘重新导入
- 根文件（MEMORY.md / SOUL.md / USER.md / MEMORY-CORE.md）常驻上下文
- 子目录只在提示里贡献 name + 一句话 description —— **分层本身就是策略，移动一个文件就是改一层**
- 写好 description 比写长正文更重要：那决定它会不会想起来去读

### 2. 每条记忆带来源
- `user`（对方亲口说的）/ `agent`（它自己的结论）/ `tool`（从文件或网页读到的）
- "一条保持自己标签的说法有用；同一条话穿上事实的衣服就是隐患"
- 旧数据默认按 `agent` 读——更保守的读法

### 3. 敏感信息分两道门
- **硬门**：身份证号、社保号、银行卡号、密码密钥、会话令牌——无论设置怎么调都拒绝，
  并告诉用户正确做法（用凭据工具，而不是写下来）
- **软门**：健康、财务、法律、家庭私事——默认排除，可配置开启，记了会一直带着敏感标签

### 4. 记忆有时效
- 每条记忆算得出「多少天前」；超阈值（默认 90 天）标陈旧并在提示里注明
- 算不出时间时用 -1 表示未知，**未知不参与比较**——不假装它很新

### 5. 审批是一等的任务状态
- 越界（动工作区外的东西）→ 任务进入 `awaiting`，这是合法中间态，不是错误分支
- 停下时把工具名和**完整参数**摆出来：你批准的是一个具体动作，不是「它想干点什么」
- 批准后重跑不会再拦（"这一次可以"，不是"我问过一次了"）
- **一键豁免但带过期**：通行证只匹配完全相同的工具名，必带过期时间——
  "没有永久允许这个选项，因为没人能替未来的自己签字"
- 改任务标题或备注会撤销批准：你批准的是当时读到的那个任务

### 6. 自主时间理由驱动
- 默认关闭；打开后空闲只是前置条件，不是理由本身
- 可检查的理由：队列里有自己的活 / 有没回应过的外部消息 / 有到点的日程 / 工作区有更新文件
- 找不到理由就明确报告「空闲够了，但没有任何符合条件的理由」——不被悄悄填满活动

### 7. 状态灯三态，不撒谎
- 绿 = 真的测过且通过；红 = 测过且失败；灰 = 还没测过
- 「没人看过」和「它没问题」不合并
- 绿点下保留上次成功和上次失败两个时刻

### 8. 工作区边界判定是纯函数
- `workspaceVerdict(toolName, args, workspace)` → inside / guarded / refused / **unchecked**
- unchecked 最重要：「查过了，没问题」和「这里没东西可查」必须在代码里分得开

### 9. 其他值得一提
- 周期任务两种语义：续跑同一上下文（例行公事）vs 另起独立任务（审计）——
  "先读自己上次的结论，一个检查就悄悄变成了橡皮图章"
- 入站消息标来源 + 限长：「谁说的」和「说了多久」都是判断的一部分
- 限额全部用户可调，0 = 不限；没有写死的配额
- 权限三档：只读 / 完全 / 仅对话，逐实例设置；自主时间默认只读

## 对麦格的映射（v0.3.0 落地项）

| dsh-bot 理念 | 麦格落地方式（Skill 行为层） |
|---|---|
| 记忆分层 | 核心常驻（人格/身份/关键偏好）vs 检索记忆（事件/事实），写进记忆规范 |
| 来源标签 | 「教麦格」写入时带 [user]/[maige]/[tool] 标签；推断不当事实引用 |
| 敏感两道门 | 硬门永不记（密码/密钥/证件号）；软门默认排除（健康/财务/法律/家庭） |
| 记忆时效 | 带日期写入；引用超过 90 天的记忆时主动注明时效 |
| 可审查 | 「你都记着我什么」→ 列出全部记忆，支持逐条删除 |
| 审批哲学 | 越界操作前摆出具体动作等批准；豁免带范围与期限；复述确认 |
| 理由驱动 | 定时/主动行为：没理由就明说「没事发生」，不硬找话 |
| 状态诚实 | 没验证过的能力明说"没试过"；「没测过」≠「没问题」 |

## 麦格做不到 / 不适合做的

- 常驻实体 + 任务队列 + 执行器：dsh-bot 是宿主侧代码实现；麦格是 Skill+Hook 层，
  MCode 的会话和权限体系已覆盖大部分场景，不重复造轮子
- 向量检索：dsh-bot 自己也明确不做（"引入 RAG 只会多一个更不可解释的层"）
- 入站连接（Telegram/HTTP）：属于远期 IM 渠道外溢，走 MaxClaw 路径更合适
